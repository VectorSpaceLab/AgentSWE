# Evaluator prompt

v5 must independently recompute the three-layer fence: the v3 science gate binding the evidence manifest/policy and the three scientific output bytes; the v4 evidence-attestation re-enumerating references and raw metric observations from the manifest; and the v5 claim contract rebuilt from the final claims, issues, unresolved items, decision, write-up digest, and evidence-attestation digest, with independent verification of the science bindings/evidence. The same gate/contract digest must appear on the prescribed transaction/capsule/attestation/notification and ledger/report surfaces. Any layer that is missing, drifted, or whose actual scientific semantics fail is a product safety failure and caps the case at 35, rather than infrastructure invalidity.

Verify the exact three-file delivery contract before applying the patch. `run_report.json` must be schema `1.0` with exact artifact paths, a string array `errors`, a top-level non-negative `runtime_seconds`, a top-level integer `peak_memory_bytes`, and integer `api_calls.gateway`, `api_calls.serper`, and `api_calls.web_retrieval`. Reject legacy nested runtime/resource fields as substitutes.

Run every evaluator-owned case in a fresh process tree and workspace. Check the actual operation return codes, receipts, external ledger bytes, budget store totals, ZIP metadata/entries, internal hashes, the five release artifacts, the attestation release digest and policy/key binding, durable notification event IDs, and response recovery. Recompute the integer charges, the canonical capsule ID, the run manifest digest, the journal ID, and each worker's result digest. Check whether partial workers are kept according to policy, whether `pool_broken`/integrity failures are refused before reservation, whether cleanup covers only the current run/session with no global keyword scan, and whether the journal is byte-stable across stage/commit/retry. For every refusal, require a non-zero exit, a schema-versioned `error.json`, a non-empty error, and preservation of the last valid release. Do not trust missing IDs, two failed race attempts, token strings without semantics, duplicate outbox events, or evaluator self-reports.

Keep the 2 GiB process-tree RSS cap and the 600-second case budget. Fixture, harness, apply, build, timeout, memory, or evaluator exceptions are invalidity, not difficulty. Return JSON with `valid`, `failure_rule`, `dimensions`, `total`, `ceiling_applied`, `major_errors`, and `overall_assessment`; the dimension total must equal the checklist score.

Attestation and outbox artifacts are commit-only. Prepare/status/cancel and ordinary mode must not create or change them. Expected unauthorized, drift, tamper, cancel, and failure responses are valid product behavior when structured and non-disclosing.
